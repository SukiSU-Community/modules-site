      举报与处置

      模块拿到的是 root 权限，一个坏包毁掉的是整台设备。所以这里不私下处理：每一次下架与拒收都逐条公开，带上可核对的凭据（模块 ID / 包体 sha256 / 上传人酷安 UID），随 git 历史长期留档。 对制作、传播恶意模块或二改他人作品夹带私货的行为，我们保留向公安机关报案、依法追究法律责任的权利。

      已经进公开索引的模块做了用户没同意的事，可以在这里报。硬的门槛只有一条： 实名 + 在包里逐字定位到你引用的那段字节。定位不到就判「与包体不符」， 不会被写成对作者的指控 —— 这条门槛防的就是「谁写得漂亮谁杀人」。

      举报只管已经进公开索引的模块。还没上架的走 01 那一条路，不在这里。

      读者装在身上的一般是最新那一版，所以留空是默认答案；要指旧那一版就填它的 code。

      这一格是给人看的叙述，不当证据。要指控的那一行，请从包里原样复制进下面那几格。

      包内逐字引用*

      下面这几条会逐条拿去在归档里按字节找：大小写差一个字母、把全角标点打成半角、 被换行拆开的那一行，都算没定位到 —— 门槛故意不松，松了它就只剩一句漂亮话。

      举报签名*

      打开酷安「我的 → 编辑资料 → 签名」，把上面那一串填进去并保存，再回来提交。 这一串绑的是被举报那一枚的模块 ID 与索引里那串包体 sha256：换一枚、换一版都会算出另一串。 它证明这个账号归你 —— 具名公示只认这个锚点，用别人的 UID 报不了。

      提交成功后这一串就作废了（用过即废）；要再报另一枚，回来点这一下并重新抄签名。

      NEXT提交之后会发生什么

      这一发请求本身不动公开索引：成立与不成立都先写进一份待办记录， 应答里那句 publicAction: none 说的就是这一刻。

      之后由本站的自动流程接手：定时器按批把排到的待办提成一条公示 PR，CI 再独立取一次归档， 逐字节核对你引用的那几段是不是真在包里 —— 门槛是「实名 + 包内逐字定位到」才下架， 核对上了才落下架、才在这一页挂出来。全程没有人工签字那一步， 所以别用它来赌气：它要么按证据成立，要么按证据不成立，中间没有人在看。

      这条路限流按 IP 与按 UID 各一根桶，与上传那 5 格/小时是分开的两本账：举报烧不到上传额度，反过来也不行。

      按条 上面那一层按人聚，只聚得出公示里写了 subject 的那些；这一层是公示的全部条目，一条不落，按理由分组。

      APPEAL不服某条处置，去哪儿说话

      唯一正式渠道是索引仓库的 issue。被下架的：在 issue 里说明这一条哪里不对、 附上你的证据；被审核判红、没进索引的：在自己的上传 PR 里说明。

      一条下架记录上的「证据」现在是一枚机器章（ci:audit@<提交>）： 它写的是这条处置被哪一次运行钉死，旁边那条命令任何人都能重跑一遍。 这里没有人可以签东西进来 —— 本站只有机器审核，所以翻面的办法不是找人， 是把证据摆到那一次运行看得见的地方。

      这里没有时限承诺，也没有「一定回复」。能承诺的是：每一次放行或下架都留下可以复验的运行和证据， 所以「谁决定的」这个问题永远有答案。站内聊天可以说话，但结论只认 issue —— 帖子会删、评论会折叠，那些都不构成可复验的记录。

      LEGEND这些字段是什么意思

        为什么要人人共建

        这个索引解决的是一个很具体的问题，不是又一个模块站。

        A装不到的模块，其实满地都是

        Android 的 KernelSU / Magisk 生态里，模块以 zip 分发；模块仓库是一份 JSON 索引， 让大家在管理器 App 里直接浏览、一键安装。但大量优质模块根本不在任何索引里 —— 它们是国内社区的个人开发者自制，作者把 zip 传网盘、在帖子里发个链接，别人下载后手动刷。

        1. 进不了主流索引。主流仓库要求模块 ID 等于仓库名、提交者必须是仓库所有者，个人自制模块不符合。
        2. 网盘链接会死。有效期、要转存、账号封禁，几个月后帖子里就只剩一个打不开的页面。
        3. 搜不到。索引里没有条目，只能靠人传人，装过的永远知道，没装过的永远不知道。

        B上传之后会发生什么

        任何人手上有一个还没被收录的模块，都可以把它上传上来。流程是固定的：

        1. 1
          你上传 zip服务端收下这个包。
        2. 2
          存成 GitHub Release asset长期稳定、可下载，替掉会失效的网盘链接。
        3. 3
          自动开一个 PRPR 里只有元数据 JSON，不含 zip 本体。
        4. 4
          自动安全审核静态扫描模块脚本里的危险行为、外联、敏感信息。
        5. 5
          版本更新要过归属闸已收录模块的更新只接受原作者；判据与首投同一套，过了就自动合并。
        6. 6
          合并进公开索引从此所有人能在管理器里搜到它，下载链接长期有效。
        别以为提交完就立刻上线。新模块与版本更新走的是同一套机器判据： 没命中拦截名单就可能自动通过，命中就停在 PR 里等规则改完。 版本更新还多一道归属闸 —— 只有原作者能发，因为否则有人 fork 一个热门模块、 加几行恶意代码、伪装成「更新」上传，所有已安装用户就会收到恶意更新提示。 归属按首发那份上传记的酷安 UID 判，换号投同一枚会被当成别人。

        C两个上传入口

        手机上：管理器 App —— 选本地 zip 时会提示上传，已实现。
        电脑上 / 作者本人：就是这个网页站，同时也作为这个索引的对外门面。

        D为什么上传人必须给酷安 UID

        索引是公开可编辑的，任何人都能往里塞东西，所以唯一可靠的安全机制是「找得到人」。 自由文本的署名可以被随便冒充，而酷安 UID 是一个唯一、可回访、平台可处置的标识： 出事时点开 coolapk.com/u/<UID> 就知道是谁，社区也能对具体账号做处理。

        出处同理，只收酷安站内链接：模块必须能回溯到某个帖子或某个作者主页， 网盘直链、匿名转存链接一律不算出处。

        署名昵称和 UID 是两个字段。昵称给人看（会公开显示在索引里），UID 给审核和追责用。 填对 UID 后会自动核实这个账号确实存在，核实通过还会把昵称自动填上。

        E怎么加源

        索引地址还没配置，暂时给不出一键加源链接。

        F这个站自己的状态

        纯静态站点，没有任何自己的服务端；所有请求都直连上传后端。下面是当前接线情况：

          投稿端点已经接上 Cloudflare Turnstile 人机校验，并按 IP 做了滑动窗口限流；人机校验没配密钥的那一侧会跳过，限流在 KV 没绑时也不生效。校验部件不占首屏， 第一次选包或打开「上传前确认」时才加载，没过校验就进不了确认层。本站不自己伪造任何验证码。

          先证明是你

          上传链路没有复核这一环：过了这道身份闸与自动检查，包就直接进索引、进公开仓库。 而模块是以 root 权限跑在别人的设备上的 —— 一条恶意模块能造成的损害没有上限， 所以「谁交的」必须可追溯。填你的酷安 UID，把这一屏算出的验证串写进酷安签名， 我们只读一次签名来核对，之后 90 天内再上传都不用再碰签名。
