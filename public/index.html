      举报与处置

      模块以 root 权限运行，一个坏包可以毁掉整台设备。所以这里不做私下处理：每次下架和拒收都逐条公开，带上可核对的凭据，随 git 历史长期留档。 对做恶意模块、或拿别人作品改一改夹私货的，我们保留报案和依法追究责任的权利。

      已经在模块库里的模块，干了用户没同意的事，可以在这里报。硬要求只有一条： 实名，并且能在包里逐字找到你引用的那段内容。找不到就判「与包体不符」， 也不会写成对作者的指控 —— 这条要求防的就是「谁写得漂亮谁杀人」。

      只能举报已经上架的模块。还没上架的走上传那条路，不在这里。

      大家装的一般是最新版，留空就行；要指旧版，填那一版的版本代号。

      这里只是给人看的说明，不算证据。要指控的代码，请从包里原样复制到下面几格。

      包内逐字引用*

      这几段会逐字拿到归档包里找：大小写差一个字母、全角标点打成半角、 被换行拆开，都算没找到 —— 要求就是这么死，松了就只剩一句漂亮话。

      打开酷安「我的」→ 点自己头像 → 右上角三点 → 「查看我的资料」里的 用户 UID。填你自己的，这条记录会署你的名。

      这里只是你自己写的，最终以 UID 查回来的昵称为准，改名的人不会被永久挡住。

      举报签名*

      打开酷安「我的 → 编辑资料 → 个性签名」，把上面那串贴进去保存，再回来提交。 这一串与被举报的模块、包体校验值绑定，更换模块或版本即会变化。 它证明这个账号是你的 —— 公示只认这个凭据，用别人的 UID 报不了。

      提交成功后这一串即作废；如需举报其他模块，返回点击「更换一串」重新填写。

      NEXT提交之后会怎样

      提交本身不会改动模块库：不管成不成立，先记进一份待办， 应答里那句 publicAction: none 说的就是这一刻。

      之后自动流程接手：定时把待办提成一条公示，再由自动检查独立取一次归档， 逐字核对你说的是不是真在包里 —— 核实了才下架、才在这一页挂出来。 全程没有人工签字，所以别拿它赌气：要么按证据成立，要么按证据不成立，中间没人在看。

      举报限流按 IP 和账号各算一份，和上传的次数分开：举报烧不到上传额度，反过来也一样。

      全部记录 上面按人分组，只分得出写了身份的；这里是一条不落的全部记录，按理由归类。

      APPEAL觉得处置不对，去哪儿说

      正式的渠道只有模块库仓库的 issue。被下架的，在 issue 里说清哪一条不对、 附上你的证据；审核没通过、没上架的，在你自己的上传说明里讲。

      每条下架记录上都有一个自动标记（ci:audit@<提交>）： 写明这条是哪一次检查判定，旁边的命令任何人可重新执行核对。 这里没有人工审批 —— 全是自动检查，想让结论翻过来，别找人， 把证据摆到那次检查看得见的地方。

      这里不承诺多久回复，也不承诺一定回复。能保证的是：每次放行或下架都留下可查的运行和证据， 所以「谁判的」永远查得到。站内聊天可以聊，但只认 issue —— 帖子会删、评论会折叠，那些都不算数。

      LEGEND这些词什么意思

        为什么要有这个站

        就解决一件很具体的事：好模块找不到，找到的又下不下来。

        A好模块，其实到处都是

        KernelSU / Magisk 的模块都是 zip，管理器从一份清单里读， 所以能浏览、能一键装。但一大堆国内作者做的模块不在任何清单里 —— zip 传网盘，帖子里发个链接，别人下下来手动刷。

        1. 主流仓库进不去。正式仓库要求模块 ID 跟仓库名一样、还得是仓库所有者才能提交，个人做的对不上。
        2. 网盘链接会死。有效期、要转存、账号一封，几个月后帖子里只剩一个打不开的页面。
        3. 搜不到。清单里没有，只能靠人传人。装过的永远知道，没装过的永远不知道。

        B传上去之后会怎样

        手上有个还没被收录的模块，谁都能传。流程是固定的：

        1. 1
          你传 zip我们收下这个包。
        2. 2
          存成长期下载地址放在 GitHub 上，稳定可下载，替掉会失效的网盘链接。
        3. 3
          自动提交审核只提交模块信息，不含 zip 本体。
        4. 4
          自动检查扫一遍脚本里的危险操作、偷偷联网和敏感信息。
        5. 5
          更新只认原作者已上架的模块，只接受第一次上传那个账号发的新版，判据和首投一样。
        6. 6
          进公共模块库从此管理器里搜得到，下载地址长期有效。
        传完不等于立刻上架。新模块和更新走同一套自动检查： 没问题就自动通过，有问题就卡住等人改规则。 更新还多一道：只有原作者能发 —— 否则有人 fork 一个热门模块、 加几行坏代码、伪装成「更新」上传，所有装了的人都会收到恶意更新。 是否原作者按第一次上传的酷安账号认，换号传同一个会被当成别人。

        C两个入口

        手机上用管理器 App，选本地 zip 时会提示上传。
        电脑上、或者作者本人，就用这个网页。

        D为什么一定要填酷安 UID

        清单是公开的，谁都能往里塞东西，所以唯一靠得住的办法是「找得到人」。 名字可以随便写，酷安 UID 是唯一的、点开就知道是谁、平台也能处理： 出事时打开 coolapk.com/u/<UID> 就清楚了，社区也能对具体账号做处理。

        来源同理，只收酷安站内链接：模块得能追到某个帖子或某个作者主页， 网盘直链、匿名转存都不算。源码只收 GitHub 上公开的那一个，两者至少填一个。

        昵称和 UID 是两回事。昵称给人看，会显示在列表里；UID 给审核和追责用。 UID 填对了会自动核实账号存在，还会把昵称填上。
